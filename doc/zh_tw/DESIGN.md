# hdd-health-check — 設計

本文件說明 `v3.0.0` 整合版本的行為,限制及主機端狀態.本文件介紹 `v3.0.0`.`v3.0.0` 原始碼標籤標記本次大版本更新;不建立 GitHub Release.使用者表示舊版 `v2.2.0` 曾在實機執行,但未提供裝置,環境與測試範圍;新版 評分僅通過隔離模擬驗證,未經實體 HDD 驗證.

通電時長僅作使用資訊,不單獨扣除健康分.ATA 預失效屬性接近閾值時,只有原始錯誤計數非零才提示關注;舊紀錄若沒有保存原始依據,則標為待複查且不扣分.關注卡片顯示已記錄的具體原因.

## 設計目標

- 透過 SMART 狀態與屬性,SMART 錯誤/自我測試紀錄,掛載資訊,核心 I/O 錯誤及趨勢,快速初步評估 HDD;提供啟發式分數及可據以採取行動的等級,而非故障機率.
- 提供可獨立執行的磁碟內部 SMART 短/長測試,抽樣原始讀取,可續掃的磁碟表面讀取延遲掃描,可選擇針對特定區域進行的唯讀 `badblocks` 重新檢查,全碟唯讀 `badblocks` 檢查,以及修復後的介面讀取壓力測試.
- 支援互動式選取,批次執行,持久保存結果,重複使用及歷史報告;長時間工作可選擇交由暫時性 systemd 單元執行.
- 不提供資料救援,寫入模式 `badblocks`,安全清除及修改檔案系統.Bash 檢查器維持單次執行;選用的本機 Web 配套服務提供常駐控制器與排程快速檢查.可選擇納入 SSD/NVMe,但 HDD 評分並非設計用來完整診斷這些裝置.JSON 快照供 Web UI 使用;深入的 SAS 評分與 NVMe 專用評分仍未實作.

## 架構

單一 Bash 4.3+ 腳本透過 `lsblk` 列舉磁碟,以選單或命令列介面選取目標,並使用 `smartctl` 探測 SMART 存取,執行所選模組及產生綜合報告.ATA SMART 屬性與 SAS/SCSI 缺陷/錯誤計數器採用不同評分路徑.快速檢查納入掛載及核心紀錄證據;速度,磁碟表面與介面檢查則直接讀取原始裝置.結果及每個裝置的識別資訊會持久保存,供後續檢查重複使用.互動式決策可透過受限的計畫傳遞給批次程序;專用鎖定機制避免使用相同狀態目錄的執行個體同時運作.如可使用 `systemd-run`,分離執行的工作會由暫時性單元處理;`--status` 與 `--stop` 會查詢已記錄的執行個體.

完整評估將快速,短測,長測 SMART,速度和完整表面掃描標為同一批次,最後複查快速 SMART/ATA/CRC.只有同批次完整且有效的結果才有數字綜合分數.重複使用,中斷,過期,無批次標記的舊狀態及後續介面複查令舊紀錄標為歷史/待複查,整體為部分/未知;報告不更新快速檢查比較基準.介面複查另行記錄已解決或未解決,不重新歸因舊錯誤或令舊批次成為目前批次.無先前快速檢查計數的 ATA 累計數原因未明,未解決的 5 分扣分在後續檢查及全套評估中保留;舊紀錄缺少風險欄位時亦按未解決處理.增加扣 20 分;計數穩定不是新錯,也不是修復證據;僅有介面複查不能把舊 ATA 錯誤歸因於介面修復.零星慢讀提示效能重測而非壞磁區診斷;表面讀取錯誤仍扣 40 分.這是啟發式權重而非故障機率.

固態碟的速度抽樣波動及與上次測試的平均速度變化僅作為效能資訊,不扣健康分;實際讀取錯誤仍會扣分.既有速度結果亦按相同規則顯示,不修改磁碟狀態檔案.Web 磁碟清單會依瀏覽器可用寬度自動排列卡片,寬螢幕最多四欄;瀏覽器縮放改變可用寬度時卡片會重新排列.儀表板的磁碟統計區塊可跳至清單.

## 設計限制

- 有效診斷需要 root 權限及實體 SMART 透傳能力.USB/RAID 橋接偵測屬啟發式判斷;透傳失敗會如實回報,不會據此推定裝置健康.SAS 評分獨立於 ATA 評分,且測試較少.溫度與門檻值取決於廠商資料.
- 所有裝置磁碟表面與介面讀取資料都會送往 `/dev/null`;執行 `badblocks` 時不使用具破壞性的 `-w`.**啟用 SMART 及執行自我測試可能改變磁碟韌體狀態**;主機上的路徑亦可寫入.不可將其描述為完全沒有副作用的執行方式.
- 明確選取裝置及使用 `--include-ssd` 並不能證明裝置可安全承受負載.全碟磁碟表面掃描可能耗時數小時;其他程序仍會繼續寫入作業系統.`--stop` 不會終止磁碟內部正在執行的自我測試.
- 狀態與計畫資料只會按允許的欄位解析,不會當作 shell 程式碼執行.既有的資料若不符合格式,可能會遭拒.主機狀態目錄不可為符號連結;腳本會檢查目錄及輸出日誌的符號連結,但使用者仍須自行保護所選路徑.

## 資料設計

`HDD_STATE_DIR` 預設為 `/var/lib/hdd-health`(建立時權限模式為 700).其中儲存 `settings.conf`(有效天數,重複使用政策,平行處理數,掃描區塊大小,抽樣參數,是否納入 SSD 及自動重新檢查政策),每個磁碟的 `.env` 結果檔,SMART 計數器 `history.csv`,修復日誌,磁碟表面掃描圖與檢查點,報告歷史紀錄,以及可選的壞區塊清單.`.lock`,執行中個體資料與暫存背景工作計畫用來協調執行.預設設定包括七天的結果有效期,64 MiB 的磁碟表面掃描區塊,以及 24 × 128 MiB 的速度抽樣.選單可儲存設定;`--rescan` 可覆寫重複使用政策.清除結果時可保留計數器/修復歷史紀錄,或連同紀錄刪除;使用者也可另外選擇刪除舊日誌.

`HDD_LOG_DIR` 預設為 `/var/log/disk-health`;`-l/--log` 可指定個別日誌.日誌為純文字,可能包含裝置識別資訊,主機/核心詳細資料與健康資料,應妥善保護.暫存工作目錄建立於 `/run`,或在必要時建立於備用暫存目錄.不可假設日誌是唯一的持久性輸出,也不可假設無須對應的備份,就能將較新版本的狀態目錄回復至舊版.

## 外部介面

| 介面 | 職責與影響 |
| --- | --- |
| `lsblk`,`blockdev`,`/proc/mounts`,核心紀錄 | 列舉裝置,取得幾何資訊,掛載狀態與 I/O 錯誤;可見資訊取決於主機權限. |
| `smartctl` | 讀取 SMART 診斷資料;可啟用 SMART 或啟動內部測試.透傳選項的自動偵測屬啟發式判斷. |
| `dd`,`badblocks` | 直接讀取原始裝置,以進行抽樣,介面負載,延遲掃描或唯讀壞區塊測試.讀取作業可能加重已劣化硬體的負擔. |
| `apt-get` | 提供安裝缺少套件的選項;`-y` 可自動接受.此操作會更動主機套件,且可能需要網路連線. |
| `systemd-run` | 用於分離執行工作的可選暫時性單元;`--stop` 要求停止腳本已記錄的程序,而非硬體自我測試. |

健康檢查本身不使用網路 API.選用的本機 Web 服務提供手動模式下僅供 loopback 使用的 HTTP API;安裝器啟用附帶驗證的區域網路存取;`--json` 則提供唯讀結構化快照,並使用與終端報告相同的綜合評分函式.`--no-install` 會停用無人值守呼叫期間的套件安裝.Web 架構,排程與安全邊界詳見 [WEB](WEB.md).腳本及整合程式可使用程序結束代碼:`0` 健康,`1` 需注意,`2` 危險,`3` 執行階段錯誤;請參閱[使用指引](README.md#使用指引).

Web 登入使用短時效,僅限 HTTP 存取的會話 Cookie.精確 IPv4 免密清單只略過一般操作的密碼輸入,編輯清單仍須密碼會話.開啟磁碟時才讀取 SMART 詳情;SMART 原始結論不取代現有綜合評分.

首頁的一鍵評估可分別選擇磁碟範圍及檢測項目.範圍包括 SATA,機械硬碟,固態硬碟,NVMe 或全部磁碟;項目包括快速檢查,SMART 短/長自檢,速度,盤面,badblocks,介面複查及完整評估.服務端按目前列舉結果選碟,在背景執行所選項目.只有完整評估可能產生目前綜合分數;SSD/NVMe 評分仍沿用機械硬碟規則,未另行校準.清單依傳輸協定及介質類型顯示 SATA SSD,NVMe SSD 等,並在背景讀取可用溫度,避免喚醒休眠硬碟.詳情頁只在裝置明確回報時顯示外形規格;不能僅憑 NVMe 或 SATA 判定是否為 M.2.SATA 版本與速率來自 smartctl 或 Linux sysfs;NVMe 的 PCIe 代數,通道數及鏈路速率來自 sysfs.按通電時間可切換小時與年/天/小時.

需要關注卡片現在會篩出有警告或異常紀錄的磁碟.檢測詳情列出原因與扣分;舊紀錄扣分但未儲存原因時會明確提示重新檢查.背景任務由已提交,執行中到完成,停止或失敗都會留下狀態紀錄與最近日誌.提交後 15 秒仍沒有執行或結束紀錄時顯示狀態未確認.返回碼 1 或 2 表示檢測完成但發現問題,並非啟動失敗.

## 目前固態硬碟評估與操作

固態硬碟與 NVMe 的完整評估包含 SMART 快檢、短測、長測及全碟唯讀掃描，不執行速度取樣。單純慢讀不扣健康分；同一批次全部檢查完成且無異常時顯示 100 分，SMART 異常或實際讀取錯誤可能扣分。選取範圍包含固態硬碟時，網頁僅提供快速檢查、短測、長測、唯讀掃描及完整評估。點擊容量或固態硬碟累計寫入量可切換十進位與二進位單位。休眠機械硬碟的 SMART 詳情可單獨喚醒該碟。
