# واجهة Web المحلية

تعرض واجهة Web نتائج الأقراص المحلية, والسجل الحديث لعدادات SMART, والمهام النشطة, وجدولًا قابلًا للضبط للفحوص السريعة. وتبدأ الفحوص المختارة عبر أداة Bash الحالية. لا تحول النتائج الجزئية أو المنتهية الصلاحية إلى درجة حالية. لا تظهر درجة رقمية إلا لتقييم مكتمل من دفعة واحدة لم تنته صلاحيتها.

تعرض بطاقات الأقراص التي تحتاج إلى انتباه سبب التنبيه المسجل. لا تخصم ساعات التشغيل وحدها من درجة الصحة؛ وتصبح تنبيهات العتبة القديمة التي تفتقر إلى عدد الأخطاء الخام بحاجة إلى مراجعة. تستخدم التأكيدات مربع حوار داخل الصفحة، وتعرض التفاصيل الطراز فوق مسار الجهاز.

## المتطلبات

- Debian أو Ubuntu مع Python 3.10+ وNode.js متوافق مع إصدار Vite المثبت في المشروع, وsystemd و`systemd-run`.
- اعتماديات الفاحص الحالية: `smartmontools`, و`util-linux`, و`coreutils`, و`e2fsprogs` اختياريًا لفحوص badblocks.
- تحتاج خدمة Web إلى صلاحيات root. يستمع مثبّت Debian على منفذ IPv4 رقم 8765 ويستخدم صفحة دخول وجلسة لواجهة API. افتح `http://<NAS-IP>:8765` من LAN موثوقة نفسها فقط؛ لا تمرر المنفذ إلى الإنترنت. لا يشفّر HTTP على الشبكة المحلية كلمة المرور. يمكن استخدام تحويل منفذ SSH المحلي للنقل المشفّر.

## البناء والتشغيل

توجد شيفرة واجهة Web الحالية في `src/web/`, ولا يتتبع المصدر بناء `dist/web/` المولّد. يحتفظ الوسم التاريخي `v3.0.0` بتخطيط `web/` القديم. على مضيف Debian يدعم systemd, ثبّت Node.js 20.19+ أو 22.12+ وnpm, ثم ابنِ الواجهة وشغّل المثبّت:

```bash
git clone https://github.com/CharlesGool/hdd-health-check.git
cd hdd-health-check/src/web
npm ci
npm run build
cd ../..
sudo bash deploy/install.sh
```


بعد فك أرشيف NAS الجاهز على Debian، ادخل إلى الدليل الناتج وشغّل:

```bash
sudo bash deploy/install.sh
```

بعد التثبيت, افتح `http://<NAS-IP>:8765` وأدخل كلمة المرور المولّدة. اقرأها باستخدام `sudo cat /root/apps/hdd-health-check/web-password`؛ ويحافظ عليها المثبّت عند التحديث ولا يقرأ ملفها إلا root. تطلب Security Settings كلمة مرور المدير قبل عرض قائمة IP أو نموذج تغيير كلمة المرور. خلال إذن الخمس دقائق, أدخل كلمة مرور جديدة من 12–128 حرفًا وأكّدها دون تكرار القديمة؛ ويلغي التغيير جميع الجلسات. إذا لم تفتح الصفحة, افحص `sudo systemctl status hdd-health-web.service` وسماح الجدار الناري بالمنفذ TCP 8765 من LAN. لا يغيّر المثبّت قواعد الجدار الناري.

من نسخة مصدر موثوقة:

```bash
cd src/web
npm ci
npm run build
cd ../..
sudo python3 src/web/server.py --port 8765
```

افتح `http://127.0.0.1:8765`. تقدم عملية Python ملفات الواجهة المبنية, ولا يلزم Node أثناء التشغيل. أبق نسخة المصدر و`dist/web` معًا. يشغل `npm run dev` خادم Vite على منفذ محلي آخر, ويوجه `/api` إلى خدمة Python.

للتشغيل الدائم استخدم المثبّت أعلاه؛ تحتاج وحدة systemd إلى ملف كلمة المرور الذي ينشئه.

لإزالة خدمة Web, شغّل `sudo systemctl disable --now hdd-health-web.service`, ثم احذف ملف الوحدة المثبّت وشغّل `sudo systemctl daemon-reload`. راجع الفحوص المؤقتة النشطة قبل إزالة نسخة المصدر. احتفظ بالحالة والسجلات أو احذفهما بشكل منفصل وفق إرشادات إزالة أداة سطر الأوامر.

عنوان `site-preview` في Codex يعرض ملفات ثابتة فقط. يمكنه عرض الواجهة وسجل التحديثات المضمّن، لكنه لا يملك واجهة `/api`، لذا لا يعرض الأقراص ولا يبدأ الفحوصات. للبيانات الفعلية افتح عنوان خدمة Python. من جهاز آخر، نفّذ `ssh -L 8765:127.0.0.1:8765 user@nas-host` على ذلك الجهاز ثم افتح `http://127.0.0.1:8765`.

يفحص المثبّت `deploy/install.sh` النظام ويثبت التطبيق في `/root/apps/hdd-health-check` ويشغّل `hdd-health-web.service`. لاحقًا افحص حالته باستخدام `sudo systemctl status hdd-health-web.service`.

قبل الترقية, انسخ `/var/lib/hdd-health` احتياطيًا مع إصدار النص البرمجي المطابق. لا تغيّر واجهة Web سياسة ترحيل حالة النص البرمجي.

## السلوك والحدود

- الفحوص السريعة التلقائية معطلة مبدئيًا. عند تفعيلها, يجري فحص كل 6-168 ساعة. يبدأ أول فحص بعد التفعيل بفترة وجيزة إذا لم يكن فحص سابق مجدولًا. يقتصر الجدول على الأقراص الدوارة, ويبدأ عبر وحدة systemd مؤقتة.
- تُختار الفحوص اليدوية لكل قرص. تتوفر لقرص SSD الفحوص السريعة واختبارات SMART القصيرة والطويلة والمسح الكامل للقراءة فقط والتقييم الكامل. تعرض ضوابط الدفعات اتحاد الوحدات المدعومة للأقراص المختارة؛ وتتجاوز وحدات HDD فقط أقراص SSD. قد تفعّل الأداة SMART أو تبدأ اختبارات ذاتية داخل القرص. يحفظ الإيقاف الآمن تقدم المسح, لكنه لا يلغي الاختبار الداخلي.
- يمنع `--no-install` خدمة Web من الموافقة على تثبيت الحزم عند بدء المهام. ثبّت الاعتماديات الناقصة بشكل منفصل. لا تقبل الخدمة إلا أسماء فحوص ثابتة وأجهزة معدودة حاليًا, ولا تستخدم shell لإنشاء الأوامر.
- يبقى دليل الحالة الخاص `/var/lib/hdd-health` والسجلات في `/var/log/disk-health`. تحفظ فيه `web-schedule.json` و`web-job.json` وإيصالات المهام المكتملة في `web-job-history/` وقائمة العناوين الخاصة ومفتاحها في `web-access.json` بصلاحيات مقيّدة. يرى المتصفح النتائج والسجل عبر JSON من المصدر نفسه.
- ترتبط خدمة المثبّت بجميع واجهات IPv4, لكنها لا تقبل إلا Host يطابق عنوان الوجهة ومنفذها. تتحقق من Origin وتتطلب جلسة كلمة مرور أو عنوان مصدر مقبولًا في القائمة لواجهات API. تظل الملفات الثابتة عامة لتحميل صفحة الدخول. لا يستطيع قراءة قائمة العناوين الخاصة ومفتاح تفعيلها أو تعديلهما إلا مدير تحققت كلمة مروره مؤخرًا؛ ويمنح الدخول عبر IP الوصول العادي للوحة فقط. يضبط الخروج ملف ارتباط يمنع الدخول التلقائي عبر IP حتى يختاره المستخدم مجددًا. لا توجد TLS؛ ويمكن لمن يراقب حركة HTTP المحلية رؤية كلمة المرور. استخدم LAN موثوقة أو نفق SSH وأبق TCP 8765 مغلقًا عن الإنترنت. يبقى الأمر اليدوي `python3 src/web/server.py` على loopback فقط ما لم تُحدد `--bind` و`--password-file`.
- عناصر التحكم متاحة بلغات المشروع الثماني. تأتي ملخصات الفحوص المفصلة وسجلات المهام المباشرة من فاحص Bash الصيني الحالي, وتبقى بالصينية مع أي من لغتي الواجهة.

## API

يعرض `GET /api/auth` حالة تسجيل الدخول؛ وتدير `POST /api/auth/login` و`/api/auth/logout` و`/api/auth/ip-login` الجلسات. يتحقق `POST /api/auth/security-verify` من كلمة مرور المدير, ويبدّل ملف ارتباط الجلسة ويمنح إذنًا ثابتًا لخمس دقائق لإعدادات الأمان. يتطلب `POST /api/auth/change-password` ذلك الإذن وتطابق كلمة المرور الجديدة مع تأكيدها؛ ويستبدل ملف كلمة المرور المملوك للجذر بصورة ذرية ويلغي الجلسات القائمة.

يتطلب `GET` و`POST /api/access` الإذن القصير نفسه لقراءة مفتاح التفعيل وعناوين IPv4 من RFC 1918 أو عناوين IPv6 المحلية الفريدة وتعديلها. يتيح `GET` و`POST /api/preferences` لأي زائر موثّق قراءة سياسة إيقاظ الأقراص النائمة عند فتح الصفحة وحفظها. يبدأ `POST /api/disks/wake-on-visit` الإيقاظ المختار في الخلفية. يقرأ `GET /api/disks/<device>/smart` تفاصيل SMART عند الطلب دون إيقاظ HDD في وضع الاستعداد؛ ويوقظ `POST /api/disks/<device>/wake` الموثّق قرصًا دوارًا معدودًا حاليًا فقط.

يعيد `GET /api/snapshot` لقطة الفاحص المنظمة, ويعيد `GET /api/status` المهمة النشطة وذيلًا محدودًا من السجل المباشر. يعيد `GET /api/jobs/history` ملخصات مهام Web المؤرشفة؛ ويعرض `GET /api/jobs/history/<id>` ذيل السجل إذا ظل متاحًا. لا يمكن إعادة بناء المهام القديمة التي حُذفت إيصالاتها بدقة. يعيد `GET /api/history/<device>` ما يصل إلى 30 صفًا من عدادات SMART للتوافق؛ ويعيد `GET /api/history/samples` عينات كل الأقراص المعدودة. يحذف `DELETE /api/history/samples/<device>/<index>` الموثّق عينة واحدة وقد يغيّر أساس المقارنة التالية إذا كانت آخر صف. يحذف `DELETE /api/jobs/history/<id>` إيصال المهمة المؤرشفة وسجلها.

يطلب `POST /api/disks/<device>/sleep` وضع ATA standby لقرص SATA HDD معدود فقط, ويرفض الطلب أثناء الفحص؛ وقد توقظه عمليات I/O العادية. يدير `GET` و`POST /api/schedule` فاصل الفحص السريع. يبدأ `POST /api/jobs` فحصًا ثابتًا على جهاز معدود. يقبل `POST /api/jobs/assess` قيمة `scope` من `sata` أو `hdd` أو `ssd` أو `nvme` أو `all`, وقيمة `module` من `quick` أو `short` أو `long` أو `speed` أو `surface` أو `badblocks` أو `iface` أو `full`؛ ويبدأ دفعة واحدة على الأقراص المطابقة. يطلب `POST /api/jobs/stop` إيقافًا آمنًا. تعيد مسارات API المجهولة 404. مخرجات `--json` من الفاحص هي مصدر التقييم, ولا تعيد خدمة Web حساب الدرجات.

## الواجهة والوصول

تظهر في الأعلى لوحة المعلومات وسجل التحديثات والإعدادات بهذا الترتيب. تبقى لوحة المعلومات نشطة في صفحات الأقراص والتنبيهات والمهام (بما فيها السجل) والفحص المجدول. لا يغير الضغط عليها من هذه الصفحات الصفحة الحالية؛ أما من الإعدادات أو سجل التحديثات فيفتح `/disks`. يظل شعار أعلى اليسار رابطًا إلى `/disks`. تفتح البطاقات الأربع `/disks` و`/attention` و`/tasks` و`/schedule`، ويبقى التقييم بنقرة واحدة في صفحة الأقراص. يفتح سجل التحديثات صفحة `/changelog` المستقلة التي يمكن فتحها مباشرة.

يرتبط اسم HDD Health أعلى اليسار بلوحة الأقراص عند `/disks`. تستخدم علامة تبويب المتصفح أيقونة المشروع من `src/web/public/favicon.svg`, المضمنة في نسخة الإنتاج. يفتح رابط إصدار منفصل بجانب العلامة سجل التغييرات. تُسمّى البنيات بلا وسم `test-<sha>` (مع `-dirty` إذا كانت الشجرة معدلة), ويعرض `/api/build` الإصدار المضمّن في البناء. لا ترسل استجابات اللقطة وSMART الافتراضية إلا الأرقام التسلسلية المخفية؛ وتحذف اللقطة العامة معرّف القرص الداخلي لأنه قد يحتوي على رقم تسلسلي؛ ويعيد طلب موثّق منفصل الرقم الكامل بعد إجراء صريح من المستخدم فقط. يُمسح عند إخفائه أو إغلاق التفاصيل.

تضم الإعدادات اللغة وثمانية ألوان بارزة ومفتاح الوضع الفاتح/الداكن، إضافة إلى سياسة سكون الأقراص. يُحفظ اللون والوضع مستقلين بعد إعادة تحميل الصفحة. وتحتوي صفحة Security Settings المنفصلة قائمة عناوين IP المسموح بها ومفتاح تفعيلها ونموذج تغيير كلمة المرور. إن غاب الإذن القصير, تطلب كلمة مرور المدير وتمنح خمس دقائق بعد التحقق. يمكن لمن دخل عبر IP استخدام ضوابط الأقراص والسكون العادية, لكنه يحتاج التحقق بكلمة مرور المدير لفتح إعدادات الأمان. خلال الإذن, أدخل كلمة مرور جديدة من 12–128 حرفًا وأكّدها دون إعادة القديمة. ينهي تغييرها جميع الجلسات. تبقى أقراص HDD النائمة ساكنة افتراضيًا؛ ويمكن اختيار إيقاظها واحدًا تلو الآخر عند فتح الصفحة. تخفي تفاصيل SMART الرقم التسلسلي حتى تفعيل زر إظهاره, وتعيد إخفاءه عند إغلاق التفاصيل.

تتيح الصفحة الرئيسية اختيار مجموعة الأقراص (SATA أو HDD أو SSD أو NVMe أو الكل) ونوع الفحص بصورة مستقلة: سريع، SMART قصير أو طويل، سرعة، سطح، badblocks، واجهة أو كامل. يختار الخادم الأقراص المدرجة حاليًا ويشغّل الفحص المحدد في الخلفية. التقييم الكامل وحده قد ينتج درجة مركبة حالية؛ وتظل درجات SSD/NVMe مبنية على قواعد HDD. تميّز القائمة SATA SSD وNVMe SSD وفق الوسيط والنقل، وتقرأ الحرارة المتاحة في الخلفية دون إيقاظ أقراص HDD النائمة. لا تعرض التفاصيل شكل القرص إلا إذا أبلغ عنه الجهاز؛ فلا يمكن استنتاج M.2 من SATA أو NVMe وحدهما. تأتي بيانات رابط SATA أو PCIe المتاحة من smartctl وLinux sysfs. انقر ساعات التشغيل للتبديل إلى السنوات والأيام والساعات.

تصفّي بطاقة التنبيه الأقراص ذات التحذيرات أو الأخطاء. تعرض التفاصيل الأسباب والنقاط المخصومة، وتطلب إعادة الفحص إذا غاب سبب قديم. تعرض صفحة المهام المهمة الجارية وسجلها المفصل، إضافة إلى سجل مستقل لآخر 30 مهمة. بعد اكتمال المهمة أو إيقافها أو فشلها، يزال الإيصال من القسم النشط ويحفظ في web-job-history/، مع بقاء نتائج الأقراص وسجلات المضيف. يدل رمزا الخروج 1 و2 على فحص اكتمل مع مشكلات.

تعرض الصفحة الرئيسية مجموع سعة الأقراص الفعلية واستخدام أنظمة الملفات المركّبة دون تكرار UUID. قد تجعل RAID ووحدات التخزين غير المركّبة القيم غير قابلة للمقارنة. تعرض تفاصيل SMART كتابة SSD من عداد NVMe القياسي أو إحصاءات ATA ذات حجم قطاع معلوم، ولا تفترض وحدة لعدادات الشركة المصنّعة. يشمل الاستخدام أيضاً تخصيص مجمعات ZFS المعروفة. يبدّل زر السعة بين TB وTiB، ويفتح زر منفصل التفاصيل.

تواصل صفحة المهام عرض المهمة الجارية وتضيف سجلًا منفصلًا لآخر 30 مهمة Web مكتملة أو متوقفة أو فاشلة. يمكن عرض نهاية السجل المفصل إن بقي ملفه. تحفظ الإيصالات الجديدة في web-job-history/؛ ولا يمكن استعادة الإيصالات المحذوفة سابقًا بصورة موثوقة. يبقى Dashboard نشطًا أعلى صفحات الأقراص والتنبيهات والمهام والفحص المجدول.

تعرض سطر القرص طرازه عنوانًا ومسار `/dev/` منفصلًا؛ وتعرض التفاصيل أيضًا مسار `/dev/`. يفتح زر مخصص التفاصيل. يشغّل الخادم دفعة `<module> --rescan` واحدة ولا يقبل مسارات أجهزة عشوائية من المتصفح. وحدة `full` وحدها تنشئ تقييمًا حاليًا. تعرض صفحة `/changelog` سجل التغييرات بصيغة Markdown. تستخدم قراءات الحرارة `smartctl -n standby` كي لا توقظ HDD نائمًا؛ ويتحقق خيار الإيقاظ أولًا باستخدام `-n standby` ثم يقرأ الخصائص عبر `smartctl`.

## تقييم SSD وعناصر التحكم الحالية

يشغّل التقييم الكامل لأقراص SSD/NVMe فحص SMART السريع والاختبارين الذاتيّين القصير والطويل ومسحًا كاملًا للقراءة فقط. لا يشغّل أخذ عينات السرعة، ولا تُنقص القراءة البطيئة وحدها نقاط الصحة. يحصل التقييم المكتمل بلا مشكلات على 100 نقطة؛ وقد تُنقص نتائج SMART أو أخطاء القراءة الفعلية هذه الدرجة التقديرية. إذا شمل الاختيار أقراص SSD، تعرض الواجهة الفحص السريع والاختبارين القصير والطويل والمسح للقراءة فقط والتقييم الكامل فقط. يمكن النقر على قيم السعة والبيانات المكتوبة للتبديل بين الوحدات العشرية والثنائية. تتيح تفاصيل SMART لقرص HDD الساكن زرًا لإيقاظ ذلك القرص وحده.
