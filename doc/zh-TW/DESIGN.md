# hdd-health-check — 設計

本文描述 `v4.0.0` 的行為,限制及主機端狀態.`v4.0.0` 標籤標示目前主要版本的分界.使用者表示較早的 `v2.2.0` 曾在實機執行,但未提供裝置,環境或測試範圍.修訂後的評分已有模擬測試及 Debian NAS 上的 Web 驗證,但尚未在實體 HDD 上完成受控的完整評估.

## 設計目標

- 透過 SMART 狀態與屬性,SMART 錯誤/自我測試紀錄,掛載資訊,核心 I/O 錯誤及趨勢,快速初步評估 HDD;提供啟發式分數及可據以採取行動的等級,而非故障機率.
- 提供可獨立執行的磁碟內部 SMART 短/長測試,抽樣原始讀取,可續掃的磁碟表面讀取延遲掃描,可選擇針對特定區域進行的唯讀 `badblocks` 重新檢查,全碟唯讀 `badblocks` 檢查,以及修復後的介面讀取壓力測試.
- 支援互動式選取,批次執行,持久保存結果,重複使用及歷史報告;長時間工作可選擇交由暫時性 systemd 單元執行.
- 不提供資料救援,寫入模式 `badblocks`,安全清除及修改檔案系統.Bash 檢查器維持單次執行;選用的本機 Web 配套服務提供常駐控制器與排程快速檢查.可選擇納入 SSD/NVMe,但 HDD 評分並非設計用來完整診斷這些裝置.JSON 快照供 Web UI 使用;深入的 SAS 評分與 NVMe 專用評分仍未實作.

## 架構

`src/checker/hdd-health-check.sh` 中的檢查器實作透過儲存庫根目錄的相容入口呼叫.它使用 `lsblk` 列舉磁碟,透過選單或命令列選擇目標,以 `smartctl` 探測 SMART 存取,執行指定模組及產生綜合報告.ATA SMART 屬性與 SAS/SCSI 缺陷/錯誤計數器採用不同評分路徑.快速檢查包含掛載和核心紀錄證據;速度,表面和介面檢查直接讀取原始裝置.結果與每個裝置的識別資訊持久保存,供後續檢查重複使用.互動式決策可透過受限計畫傳遞給批次程序;私人鎖定機制防止共用狀態目錄的執行個體同時運作.可用時以暫時性 `systemd-run` 單元處理分離式工作;`--status` 和 `--stop` 查詢已記錄的執行個體.

完整批次以同一標記記錄快速,短測,長測 SMART 檢查及已完成的唯讀表面掃描;網頁批次選項展示所選磁碟支援項目的聯集,僅適用於 HDD 的模組會跳過不適用的 SSD;HDD 另須速度取樣.SSD 慢讀只記錄為效能變化,不扣健康分,但實際讀取錯誤仍會扣分.批次最後複查快速 SMART/ATA/CRC,記錄掃描後變化.只有同批次完整且有效的結果才有數字綜合分數.重複使用,中斷,過期,無批次標記的舊狀態和後續介面驗證,會讓舊紀錄維持歷史/待複查狀態,整體等級為部分/未知.僅產生報告不更新快檢比較基準.介面驗證另行記錄已解決或未解決,不重新歸因舊錯誤,也不讓舊批次變成目前批次.沒有先前快檢計數的 ATA 總數仍屬未解決風險(扣 5 分);後續檢查及完整評估繼續保留,即使舊紀錄缺少風險欄位.總數增加扣 20 分;計數穩定既不證明問題解決,也不構成新錯誤.介面驗證不能單獨把 ATA 錯誤歸因於介面維修.零星慢讀提示重測效能,並非壞磁區診斷;反覆發生的表面讀取錯誤仍扣 40 分.這些是啟發式權重,不是故障機率.

快檢通電時間顯示為使用資訊,本身不扣健康分.ATA Pre-fail 屬性的近閾值警告需要非零原始錯誤計數佐證;沒有保存原始證據的歷史閾值警告改為待複查,不扣分.新警告紀錄包含 SMART 屬性及測量值.關注卡片直接顯示保存的檢查原因.網頁檢查和停止確認使用可透過鍵盤操作的站內對話框,詳情抽屜以型號為標題,裝置路徑列於下方.

固態碟的速度抽樣波動及與上次測試的平均速度變化僅作為效能資訊,不扣健康分;實際讀取錯誤仍會扣分.既有速度結果亦按相同規則顯示,不修改磁碟狀態檔案.Web 磁碟清單會依瀏覽器可用寬度自動排列卡片,寬螢幕最多六欄;瀏覽器縮放改變可用寬度時卡片會重新排列.儀表板的磁碟統計區塊可跳至清單.前端原始碼位於 `src/web/`,建置至 `dist/web/`;`src/web/src/theme.css` 為淺色和深色模式的八組強調色定義語意變數.設定頁將強調色與明暗模式分別儲存於瀏覽器,並在 Vue 掛載前還原.Vite 嵌入建置版本並產生供 `/api/build` 使用的 `version.json`;更新紀錄從打包的原始碼中呈現相應的 `doc/<lang>/LOG.md`.磁碟序號在外層清單和 SMART 詳情中維持遮蔽,直到使用者按下有標籤的顯示按鈕;關閉詳情後再次遮蔽.

## 設計限制

- 有效診斷需要 root 權限及實體 SMART 透傳能力.USB/RAID 橋接偵測屬啟發式判斷;透傳失敗會如實回報,不會據此推定裝置健康.SAS 評分獨立於 ATA 評分,且測試較少.溫度與門檻值取決於廠商資料.
- 所有裝置磁碟表面與介面讀取資料都會送往 `/dev/null`;執行 `badblocks` 時不使用具破壞性的 `-w`.**啟用 SMART 及執行自我測試可能改變磁碟韌體狀態**;主機上的路徑亦可寫入.不可將其描述為完全沒有副作用的執行方式.
- 明確選取裝置及使用 `--include-ssd` 並不能證明裝置可安全承受負載.全碟磁碟表面掃描可能耗時數小時;其他程序仍會繼續寫入作業系統.`--stop` 不會終止磁碟內部正在執行的自我測試.
- 狀態與計畫資料只會按允許的欄位解析,不會當作 shell 程式碼執行.既有的資料若不符合格式,可能會遭拒.主機狀態目錄不可為符號連結;腳本會檢查目錄及輸出日誌的符號連結,但使用者仍須自行保護所選路徑.

## 資料設計

`HDD_STATE_DIR` 預設為 `/var/lib/hdd-health`(建立時權限模式為 700).其中儲存 `settings.conf`(有效天數,重複使用政策,平行處理數,掃描區塊大小,抽樣參數,是否納入 SSD 及自動重新檢查政策),每個磁碟的 `.env` 結果檔,SMART 計數器 `history.csv`,修復日誌,磁碟表面掃描圖與檢查點,報告歷史紀錄,以及可選的壞區塊清單.`.lock`,執行中個體資料與暫存背景工作計畫用來協調執行.預設設定包括七天的結果有效期,64 MiB 的磁碟表面掃描區塊,以及 24 × 128 MiB 的速度抽樣.選單可儲存設定;`--rescan` 可覆寫重複使用政策.清除結果時可保留計數器/修復歷史紀錄,或連同紀錄刪除;使用者也可另外選擇刪除舊日誌.

`HDD_LOG_DIR` 預設為 `/var/log/disk-health`;`-l/--log` 可指定個別日誌.日誌為純文字,可能包含裝置識別資訊,主機/核心詳細資料與健康資料,應妥善保護.暫存工作目錄建立於 `/run`,或在必要時建立於備用暫存目錄.不可假設日誌是唯一的持久性輸出,也不可假設無須對應的備份,就能將較新版本的狀態目錄回復至舊版.

## 外部介面

| 介面 | 職責與影響 |
| --- | --- |
| `lsblk`,`blockdev`,`/proc/mounts`,核心紀錄 | 列舉裝置,取得幾何資訊,掛載狀態與 I/O 錯誤;可見資訊取決於主機權限. |
| `smartctl` | 讀取 SMART 診斷資料;可啟用 SMART 或啟動內部測試.透傳選項的自動偵測屬啟發式判斷. |
| `dd`,`badblocks` | 直接讀取原始裝置,以進行抽樣,介面負載,延遲掃描或唯讀壞區塊測試.讀取作業可能加重已劣化硬體的負擔. |
| `apt-get` | 提供安裝缺少套件的選項;`-y` 可自動接受.此操作會更動主機套件,且可能需要網路連線. |
| `systemd-run` | 用於分離執行工作的可選暫時性單元;`--stop` 要求停止腳本已記錄的程序,而非硬體自我測試. |

健康檢查本身不使用網路 API.選用的本機 Web 服務在手動模式下使用回環 API;安裝程式啟用經驗證的區域網路存取.`--json` 使用與終端報告相同的綜合評分函式提供結構化唯讀快照.Web 登入核發短時效,僅供 HTTP 使用的會話 Cookie.安全驗證會輪換該 Cookie,然後授予五分鐘權限;變更狀態的請求包含同源請求標頭作為 CSRF 防護.私人地址允許清單啟用後可在一般操作中略過密碼登入.Security Settings 將允許清單,啟用開關及密碼變更置於伺服端強制執行的五分鐘權限之後,該權限由管理員密碼驗證授予.僅透過 IP 進入的會話不能讀取或修改這些設定.在權限有效期間,變更密碼只須輸入並確認新密碼,不用再次輸入目前密碼;變更後所有會話失效.預設快照和 SMART 回應會遮蔽序號;只有使用者明確操作後,獨立且經驗證的顯示端點才傳回完整序號.服務只在開啟磁碟時按需讀取 SMART 詳情;原始 SMART 結論不取代檢查器的綜合分數.`--no-install` 防止無人值守呼叫時安裝套件.Web 架構,排程及安全邊界見 [WEB](WEB.md).Web 原始碼位於 `src/web/`,產生的建置結果位於 `dist/web/`;安裝程式將其複製到既有主機布局.腳本可使用結束代碼 `0` 健康,`1` 需注意,`2` 危險,`3` 執行階段錯誤;請參閱[指南](README.md#指南).

`lsblk` 提供磁碟快照中的已掛載檔案系統資料.首頁的一鍵評估可分別選擇磁碟範圍及檢測項目.範圍包括 SATA,機械硬碟,固態硬碟,NVMe 或全部磁碟;項目包括快速檢查,SMART 短/長自檢,速度,盤面,badblocks,介面複查及完整評估.服務端按目前列舉結果選碟,在背景執行 `<module> --rescan` 批次.只有完整評估可能產生目前綜合分數;SSD/NVMe 評分仍沿用機械硬碟規則,未另行校準.清單依傳輸協定及介質類型顯示 SATA SSD,NVMe SSD 等,並在背景讀取可用溫度,避免喚醒休眠硬碟.詳情頁只在裝置明確回報時顯示外形規格;不能僅憑 NVMe 或 SATA 判定是否為 M.2.SATA 版本與速率來自 smartctl 或 Linux sysfs;NVMe 的 PCIe 代數,通道數及鏈路速率來自 sysfs.按通電時間可切換小時與年/天/小時.

需要關注卡片現在會篩出有警告或異常紀錄的磁碟.檢測詳情列出原因與扣分;舊紀錄扣分但未儲存原因時會明確提示重新檢查.背景任務由已提交,執行中到完成,停止或失敗都會留下狀態紀錄與最近日誌.提交後 15 秒仍沒有執行或結束紀錄時顯示狀態未確認.返回碼 `1` 或 `2` 表示檢測完成但發現問題,並非啟動失敗.

## 目前固態硬碟評估與操作

固態硬碟和 NVMe 的完整評估包含 SMART 快檢,短測,長測及全碟唯讀掃描,不取樣速度.單純慢讀不扣健康分;無異常而完成的批次得 100 分,SMART 異常或實際讀取錯誤可能降低啟發式分數.以 `--include-ssd` 納入 SSD 時,Web UI 只提供快檢,短測,長測,全碟唯讀掃描及完整評估.點擊容量及主機寫入量可切換十進位與二進位單位.休眠 HDD 可在 SMART 詳情中單獨喚醒.
