# hdd-health-check — 設計

本文說明 `v3.0.0` 整合版本的行為,限制及主機端狀態.本文件介紹 `v3.0.0`.`v3.0.0` 原始碼標籤標記本次大版本更新;不建立 GitHub Release.用戶表示舊版 `v2.2.0` 曾在實機執行,但未提供裝置,環境及測試範圍;新版 評分只經隔離模擬驗證,未經真實 HDD 驗證.

通電時長僅作使用資訊,不單獨扣除健康分.ATA 預失效屬性接近閾值時,只有原始錯誤計數非零才提示關注;舊紀錄若沒有保存原始依據,則標為待覆核且不扣分.關注卡片顯示已記錄的具體原因.

## 設計目標

- 利用 SMART 狀態及屬性,SMART 錯誤/自我測試日誌,掛載狀態,核心 I/O 錯誤和趨勢快速評估 HDD;提供啟發式評分及可據以行動的等級,而非故障概率.
- 分別提供磁碟內部的 SMART 短測試/長測試,抽樣原始讀取,可續掃的表面延遲掃描,可選擇針對特定位置以唯讀 `badblocks` 複查,全碟唯讀 `badblocks` 檢查,以及維修後的介面讀取壓力測試.
- 支援互動式選取,批次執行,結果持久儲存,重用及歷史報告;長時間工作可選擇交由暫時性 systemd unit 執行.
- 不包括數據復原,寫入模式 `badblocks`,安全抹除及檔案系統修改.Bash 檢查器維持單次執行;可選的本機 Web 配套服務提供常駐控制器及定時快速檢查.可選擇納入 SSD/NVMe,但 HDD 評分並非設計用來全面診斷這類裝置.JSON 快照供 Web UI 使用;更深入的 SAS 評分及 NVMe 專用評分仍未實作.

## 架構

單一 Bash 4.3+ 腳本使用 `lsblk` 列出磁碟,以選單或 CLI 選取目標,透過 `smartctl` 探測 SMART 存取,執行指定模組並產生綜合報告.ATA SMART 屬性與 SAS/SCSI 缺陷/錯誤計數器使用不同的評分流程.快速檢查包含掛載及核心日誌證據;速度,表面及介面檢查會直接讀取原始裝置.結果及各裝置識別資料會持久儲存,以供往後檢查重用.互動式選擇可透過受限制的計劃傳遞至批次程序;私有鎖防止使用相同狀態目錄的實例並行執行.在可用時,暫時性的 `systemd-run` unit 負責脫離終端的工作;`--status` 及 `--stop` 查詢已記錄的實例.

完整評估將快速,短測試,長測試 SMART,速度和完整表面掃描標為同一批次,最後複查快速 SMART/ATA/CRC.只有同批次完整且有效的結果才有數字綜合評分.重用,中斷,過期,無批次標記的舊狀態及後續介面複查令舊紀錄標為歷史/待複查,整體為部分/未知;報告不更新快速檢查比較基準.介面複查另行記錄已解決或未解決,不重新歸因舊錯誤或令舊批次成為目前批次.無先前快速檢查計數的 ATA 累計數原因未明,未解決的 5 分扣分在後續檢查及全檢中保留;舊紀錄缺少風險欄位時亦按未解決處理.增加扣 20 分;計數穩定不是新錯,也不是修復證據;僅有介面複查不能把舊 ATA 錯誤歸因於介面維修.零星慢讀提示效能重測而非壞磁區診斷;表面讀取錯誤仍扣 40 分.這是啟發式權重而非故障概率.

固態硬碟的速度抽樣波動及與上次測試的平均速度變化只作效能資訊,不扣健康分;實際讀取錯誤仍會扣分.現有速度結果亦按相同規則顯示,不修改磁碟狀態檔案.Web 磁碟清單會按瀏覽器可用寬度自動排列卡片,寬螢幕最多四欄;瀏覽器縮放改變可用寬度時卡片會重新排列.儀表板的磁碟統計區塊可跳至清單.

## 設計限制

- 有效診斷需要 root 權限及實體 SMART 透傳能力.USB/RAID 橋接偵測屬啟發式;透傳失敗會如實報告,不會推斷磁碟健康.SAS 評分與 ATA 不同,且測試程度較低.溫度及閾值取決於廠商數據.
- 所有裝置表面及介面讀取均指向 `/dev/null`;呼叫 `badblocks` 時不使用破壞性的 `-w`.**啟用 SMART 及自我測試可能改變磁碟韌體狀態**;主機上的路徑亦可寫入.不可將執行過程描述為完全沒有副作用.
- 明確選取裝置或指定 `--include-ssd`,都不代表裝置能安全承受負載.全碟表面掃描可能需時數小時;其他程序的作業系統寫入仍會繼續.`--stop` 不會終止磁碟內部正在執行的自我測試.
- 狀態及計劃數據只按允許的欄位解析,不會當作 shell 程式碼執行.既有但不符合規範的狀態可能被拒絕.主機狀態目錄不可為符號連結;腳本會檢查目錄及輸出日誌的符號連結,但呼叫者仍須保護自己選用的路徑.

## 數據設計

`HDD_STATE_DIR` 預設為 `/var/lib/hdd-health`(以 700 權限建立).其中存放 `settings.conf`(有效天數,重用政策,並行數,掃描區塊大小,抽樣參數,是否納入 SSD 及自動複查政策),每隻磁碟的 `.env` 結果檔,SMART 計數器 `history.csv`,維修日誌,表面狀態圖/檢查點,報告歷史紀錄及可選的壞區塊清單.`.lock`,執行中實例資料和暫存的背景工作計劃負責協調執行.預設設定包括七天結果有效期,64 MiB 表面掃描區塊及 24 × 128 MiB 速度抽樣.選單可儲存設定;`--rescan` 會覆蓋重用設定.清除結果時可保留或刪除計數器/維修歷史紀錄;使用者亦可另外選擇刪除舊日誌.

`HDD_LOG_DIR` 預設為 `/var/log/disk-health`;`-l/--log` 可指定單一日誌.日誌為純文字,可能包含裝置識別資料,主機/核心細節及健康數據,應妥善保護.暫存工作目錄會建立在 `/run` 下,或使用後備暫存目錄.不可假設日誌是唯一的持久輸出,亦不可假設沒有配套備份便能將較新版本的狀態目錄回退.

## 外部介面

| 介面 | 職責及影響 |
| --- | --- |
| `lsblk`,`blockdev`,`/proc/mounts`,核心日誌 | 列出裝置,取得幾何資訊,掛載狀態及 I/O 錯誤;可見資料取決於主機權限. |
| `smartctl` | 讀取 SMART 診斷數據;可啟用 SMART 或啟動內部測試.透傳選項的自動偵測屬啟發式. |
| `dd`,`badblocks` | 直接讀取原始裝置,以作抽樣,介面負載,延遲掃描或唯讀壞區塊測試.讀取可能令狀況欠佳的硬件承受壓力. |
| `apt-get` | 提議安裝缺少的套件;`-y` 可自動接受.這會更改主機套件,亦可能需要網絡連線. |
| `systemd-run` | 用於脫離終端工作的可選暫時性 unit;`--stop` 要求關閉腳本已記錄的程序,而非硬件自我測試. |

健康檢查本身不使用網絡 API.可選的本機 Web 服務提供手動模式下只供 loopback 使用的 HTTP API;安裝器啟用帶認證的局域網存取;`--json` 則提供唯讀結構化快照,使用與終端報告相同的綜合評分函數.`--no-install` 停用無人值守呼叫期間的套件安裝.Web 架構,排程及安全邊界詳見 [WEB](WEB.md).腳本及整合工具可按程序退出碼判斷:`0` 健康,`1` 需要留意,`2` 危險,`3` 執行時失敗;參閱[使用指引](README.md#使用指引).

Web 登入使用短時效,僅限 HTTP 存取的會話 Cookie.精確 IPv4 免密清單只略過一般操作的密碼輸入,編輯清單仍須密碼會話.開啟磁碟時才讀取 SMART 詳情;SMART 原始結論不取代現有綜合評分.

主頁的一鍵評估可分別選擇磁碟範圍及檢測項目.範圍包括 SATA,機械硬碟,固態硬碟,NVMe 或全部磁碟;項目包括快速檢查,SMART 短/長自檢,速度,盤面,badblocks,介面複查及完整評估.服務端按目前列舉結果選碟,在背景執行所選項目.只有完整評估可能產生目前綜合分數;SSD/NVMe 評分仍沿用機械硬碟規則,未另行校準.清單按傳輸協定及介質類型顯示 SATA SSD,NVMe SSD 等,並在背景讀取可用溫度,避免喚醒休眠硬碟.詳情頁只在裝置明確回報時顯示外形規格;不能僅憑 NVMe 或 SATA 判定是否為 M.2.SATA 版本及速率來自 smartctl 或 Linux sysfs;NVMe 的 PCIe 代數,通道數及鏈路速率來自 sysfs.按通電時間可切換小時與年/天/小時.

需要關注卡片現會篩出有警告或異常紀錄的磁碟.檢測詳情列出原因及扣分;舊紀錄扣分但未儲存原因時會明確提示重新檢查.背景任務由已提交,執行中到完成,停止或失敗都會留下狀態紀錄及最近日誌.提交後 15 秒仍沒有執行或結束紀錄時顯示狀態未確認.返回碼 1 或 2 表示檢測完成但發現問題,並非啟動失敗.

## 目前固態硬碟評估與操作

固態硬碟及 NVMe 的完整評估包括 SMART 快檢,短測,長測及全碟唯讀掃描,不執行速度取樣.單純慢讀不扣健康分;同一批次全部檢查完成而且沒有異常時顯示 100 分,SMART 異常或實際讀取錯誤可能扣分.選取範圍包含固態硬碟時,網頁只提供快速檢查,短測,長測,唯讀掃描及完整評估.按容量或固態硬碟累計寫入量可切換十進制與二進制單位.休眠中的機械硬碟可在 SMART 詳情中單獨喚醒.
