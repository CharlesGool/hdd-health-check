## 設計目標

- 利用 SMART 狀態及屬性、SMART 錯誤／自我測試日誌、掛載狀態、核心 I/O 錯誤和趨勢快速評估 HDD；提供啟發式評分及可據以行動的等級，而非故障概率。
- 分別提供磁碟內部的 SMART 短測試／長測試、抽樣原始讀取、可續掃的表面延遲掃描、可選擇針對特定位置以唯讀 `badblocks` 複查、全碟唯讀 `badblocks` 檢查，以及維修後的介面讀取壓力測試。
- 支援互動式選取、批次執行、結果持久儲存、重用及歷史報告；長時間工作可選擇交由暫時性 systemd unit 執行。
- 不包括數據復原、寫入模式 `badblocks`、安全抹除、檔案系統修改及常駐監控 daemon。可選擇納入 SSD/NVMe，但 HDD 評分並非設計用來全面診斷這類裝置。結構化 JSON/CSV、更深入的 SAS 評分及 NVMe 專用評分均不是已實作的目標。

## 架構

單一 Bash 4.3+ 腳本使用 `lsblk` 列出磁碟，以選單或 CLI 選取目標，透過 `smartctl` 探測 SMART 存取，執行指定模組並產生綜合報告。ATA SMART 屬性與 SAS/SCSI 缺陷／錯誤計數器使用不同的評分流程。快速檢查包含掛載及核心日誌證據；速度、表面及介面檢查會直接讀取原始裝置。結果及各裝置識別資料會持久儲存，以供往後檢查重用。互動式選擇可透過受限制的計劃傳遞至批次程序；私有鎖防止使用相同狀態目錄的實例並行執行。在可用時，暫時性的 `systemd-run` unit 負責脫離終端的工作；`--status` 及 `--stop` 查詢已記錄的實例。

## 設計限制

- 有效診斷需要 root 權限及實體 SMART 透傳能力。USB/RAID 橋接偵測屬啟發式；透傳失敗會如實報告，不會推斷磁碟健康。SAS 評分與 ATA 不同，且測試程度較低。溫度及閾值取決於廠商數據。
- 所有裝置表面及介面讀取均指向 `/dev/null`；呼叫 `badblocks` 時不使用破壞性的 `-w`。**啟用 SMART 及自我測試可能改變磁碟韌體狀態**；主機上的路徑亦可寫入。不可將執行過程描述為完全沒有副作用。
- 明確選取裝置或指定 `--include-ssd`，都不代表裝置能安全承受負載。全碟表面掃描可能需時數小時；其他程序的作業系統寫入仍會繼續。`--stop` 不會終止磁碟內部正在執行的自我測試。
- 狀態及計劃數據只按允許的欄位解析，不會當作 shell 程式碼執行。既有但不符合規範的狀態可能被拒絕。主機狀態目錄不可為符號連結；腳本會檢查目錄及輸出日誌的符號連結，但呼叫者仍須保護自己選用的路徑。

## 數據設計

`HDD_STATE_DIR` 預設為 `/var/lib/hdd-health`（以 700 權限建立）。其中存放 `settings.conf`（有效天數、重用政策、並行數、掃描區塊大小、抽樣參數、是否納入 SSD 及自動複查政策）、每隻磁碟的 `.env` 結果檔、SMART 計數器 `history.csv`、維修日誌、表面狀態圖／檢查點、報告歷史紀錄及可選的壞區塊清單。`.lock`、執行中實例資料和暫存的背景工作計劃負責協調執行。預設設定包括七天結果有效期、64 MiB 表面掃描區塊及 24 × 128 MiB 速度抽樣。選單可儲存設定；`--rescan` 會覆蓋重用設定。清除結果時可保留或刪除計數器／維修歷史紀錄；使用者亦可另外選擇刪除舊日誌。

`HDD_LOG_DIR` 預設為 `/var/log/disk-health`；`-l/--log` 可指定單一日誌。日誌為純文字，可能包含裝置識別資料、主機／核心細節及健康數據，應妥善保護。暫存工作目錄會建立在 `/run` 下，或使用後備暫存目錄。不可假設日誌是唯一的持久輸出，亦不可假設沒有配套備份便能將較新版本的狀態目錄回退。

## 外部介面

| 介面 | 職責及影響 |
| --- | --- |
| `lsblk`、`blockdev`、`/proc/mounts`、核心日誌 | 列出裝置、取得幾何資訊、掛載狀態及 I/O 錯誤；可見資料取決於主機權限。 |
| `smartctl` | 讀取 SMART 診斷數據；可啟用 SMART 或啟動內部測試。透傳選項的自動偵測屬啟發式。 |
| `dd`、`badblocks` | 直接讀取原始裝置，以作抽樣、介面負載、延遲掃描或唯讀壞區塊測試。讀取可能令狀況欠佳的硬件承受壓力。 |
| `apt-get` | 提議安裝缺少的套件；`-y` 可自動接受。這會更改主機套件，亦可能需要網絡連線。 |
| `systemd-run` | 用於脫離終端工作的可選暫時性 unit；`--stop` 要求關閉腳本已記錄的程序，而非硬件自我測試。 |

健康檢查本身不使用網絡 API。腳本及整合工具可按程序退出碼判斷：`0` 健康、`1` 需要留意、`2` 危險、`3` 執行時失敗；參閱[使用指引](README.md#使用指引)。目前沒有穩定的結構化輸出 API。
