# स्थानीय Web UI

Web UI स्थानीय डिस्क के परिणाम, हाल का SMART काउंटर इतिहास, चल रहे कार्य और बदली जा सकने वाली त्वरित जाँच समय-सारणी दिखाता है। यह मौजूदा Bash टूल से चुनी हुई जाँचें शुरू करता है। आंशिक या समय-सीमा पार कर चुके परिणाम को वर्तमान अंक नहीं माना जाता। केवल एक ही बैच का पूर्ण और वैध आकलन संख्यात्मक अंक दिखा सकता है।

ध्यान देने वाली डिस्क के कार्ड अब दर्ज कारण दिखाते हैं। केवल चालू रहने के घंटे स्वास्थ्य अंक नहीं घटाते; पुराने थ्रेशोल्ड संकेत, जिनमें मूल त्रुटि संख्या नहीं है, पुनः जाँच के लिए चिह्नित होते हैं। पुष्टि के लिए पृष्ठ के भीतर संवाद और विवरण में मॉडल के नीचे डिवाइस पथ दिखता है।

## आवश्यकताएँ

- Debian या Ubuntu, Python 3.10+, शामिल Vite संस्करण के अनुकूल Node.js, systemd और `systemd-run`।
- मौजूदा जाँचकर्ता की निर्भरताएँ: `smartmontools`, `util-linux`, `coreutils` और badblocks के लिए वैकल्पिक `e2fsprogs`।
- Web सेवा के लिए root चाहिए. Debian इंस्टॉलर IPv4 पोर्ट 8765 पर सुनता है; Web लॉगिन और API सत्र का उपयोग करता है. उसी विश्वसनीय LAN पर `http://<NAS-IP>:8765` खोलें; पोर्ट इंटरनेट पर अग्रेषित न करें. LAN HTTP पासवर्ड एन्क्रिप्ट नहीं करता. एन्क्रिप्टेड परिवहन के लिए SSH स्थानीय पोर्ट फ़ॉरवर्ड का उपयोग करें.

## बनाना और चलाना

वर्तमान स्रोत का Web UI कोड `src/web/` में है और बना हुआ `dist/web/` संस्करण ट्रैक नहीं होता. ऐतिहासिक `v3.0.0` टैग में पुराना `web/` लेआउट है. Debian systemd होस्ट पर Node.js 20.19+ या 22.12+ और npm स्थापित करके UI बनाएं, फिर इंस्टॉलर चलाएं:

```bash
git clone https://github.com/CharlesGool/hdd-health-check.git
cd hdd-health-check/src/web
npm ci
npm run build
cd ../..
sudo bash deploy/install.sh
```


Debian NAS पर पहले से निर्मित संग्रह निकालें, निकाले गए फ़ोल्डर में जाएँ और चलाएँ:

```bash
sudo bash deploy/install.sh
```

इंस्टॉलेशन के बाद `http://<NAS-IP>:8765` खोलें और Web लॉगिन पर बना पासवर्ड डालें. उसे `sudo cat /root/apps/hdd-health-check/web-password` से पढ़ें; इंस्टॉलर अपडेट में उसे बचाता है, और फ़ाइल केवल root पढ़ सकता है. Security Settings IP सूची या पासवर्ड फ़ॉर्म दिखाने से पहले प्रशासक पासवर्ड सत्यापित करता है. पाँच मिनट की अनुमति में 12–128 अक्षरों का नया पासवर्ड और पुष्टि भरें; पुराना पासवर्ड दोबारा नहीं चाहिए. बदलाव सभी सत्र समाप्त करता है. पृष्ठ न खुले तो `sudo systemctl status hdd-health-web.service` और LAN से TCP 8765 की फ़ायरवॉल पहुँच देखें; इंस्टॉलर फ़ायरवॉल नहीं बदलता.

विश्वसनीय checkout से:

```bash
cd src/web
npm ci
npm run build
cd ../..
sudo python3 src/web/server.py --port 8765
```

`http://127.0.0.1:8765` खोलें। Python प्रक्रिया बिल्ड किया हुआ UI उपलब्ध कराती है; संचालन के समय Node की ज़रूरत नहीं होती। स्रोत checkout और उसका `dist/web` साथ रहने चाहिए। `npm run dev` दूसरे स्थानीय पोर्ट पर Vite चलाता है और `/api` को Python सेवा तक प्रॉक्सी करता है।

स्थायी सेवा के लिए ऊपर का स्थापक उपयोग करें; systemd यूनिट को उसके बनाए पासवर्ड फ़ाइल की आवश्यकता है।

Web सेवा हटाने के लिए `sudo systemctl disable --now hdd-health-web.service` चलाएँ, उसकी इंस्टॉल की गई यूनिट फ़ाइल हटाएँ और `sudo systemctl daemon-reload` चलाएँ। checkout हटाने से पहले सक्रिय अस्थायी जाँचें देखें। CLI के अनइंस्टॉल निर्देशों के अनुसार स्थिति डेटा और लॉग को अलग से रखें या हटाएँ।

Codex का `site-preview` पता केवल स्थिर फ़ाइलें दिखाता है। इसमें इंटरफ़ेस और साथ में दिया गया परिवर्तन विवरण दिख सकता है, लेकिन डिस्क डेटा या जाँच शुरू करने के लिए आवश्यक `/api` बैकएंड नहीं है। वास्तविक डेटा के लिए Python सेवा का पता खोलें। दूसरे कंप्यूटर पर `ssh -L 8765:127.0.0.1:8765 user@nas-host` चलाएँ, फिर वहाँ `http://127.0.0.1:8765` खोलें।

इंस्टॉलर `deploy/install.sh` जाँचकर सेवा को `/root/apps/hdd-health-check` में स्थापित करता है और `hdd-health-web.service` शुरू करता है. बाद में स्थिति देखने के लिए `sudo systemctl status hdd-health-web.service` चलाएं.

अपग्रेड से पहले मिलते स्क्रिप्ट संस्करण के साथ `/var/lib/hdd-health` का बैकअप लें. Web UI स्क्रिप्ट की स्थिति स्थानांतरण नीति नहीं बदलता.

## व्यवहार और सीमाएँ

- स्वचालित त्वरित जाँचें शुरू में बंद रहती हैं। सक्रिय करने पर जाँच हर 6–168 घंटे में चलती है। यदि पहले कोई जाँच निर्धारित नहीं हुई है, तो पहली जाँच सक्रिय करने के थोड़ी देर बाद शुरू होती है। समय-सारणी केवल घूमने वाली डिस्क पर चलती है और अस्थायी systemd यूनिट के माध्यम से शुरू होती है।
- मैनुअल जाँच प्रति डिस्क चुनी जाती है. SSD पर त्वरित, SMART छोटे/लंबे, पूरी डिस्क के केवल-पठन स्कैन और पूर्ण आकलन उपलब्ध हैं. बैच नियंत्रण चुनी डिस्कों के समर्थित मॉड्यूल का संयुक्त सेट दिखाते हैं; HDD-केवल मॉड्यूल SSD को छोड़ते हैं. टूल SMART सक्रिय कर सकता है या डिस्क के भीतर स्व-परीक्षण शुरू कर सकता है. सुरक्षित रोक सतह स्कैन की प्रगति बचाती है, लेकिन आंतरिक स्व-परीक्षण रद्द नहीं करती.
- `--no-install` Web सेवा को कार्य शुरू करते समय पैकेज इंस्टॉलेशन मंज़ूर करने से रोकता है। अनुपस्थित निर्भरताएँ अलग से इंस्टॉल करें। Web सेवा केवल तय जाँच नाम और उस समय सूचीबद्ध डिवाइस स्वीकार करती है; कमांड बनाने के लिए shell का उपयोग नहीं करती।
- निजी स्थिति निर्देशिका `/var/lib/hdd-health` और लॉग निर्देशिका `/var/log/disk-health` बनी रहती हैं. `web-schedule.json`, `web-job.json`, `web-job-history/` के पूरे कार्य रिकॉर्ड और `web-access.json` में निजी-पते की अनुमति-सूची तथा सक्रिय स्विच सीमित अनुमतियों के साथ उसी निर्देशिका में रहते हैं. ब्राउज़र समान-मूल JSON से स्वास्थ्य परिणाम और इतिहास देखता है.
- इंस्टॉलर सेवा सभी IPv4 इंटरफ़ेस पर सुनती है, पर केवल गंतव्य IP और पोर्ट से मिलता Host स्वीकार करती है. यह Origin जाँचती है और API के लिए पासवर्ड सत्र या सूची में दर्ज स्रोत IP माँगती है. स्थिर फ़ाइलें सार्वजनिक हैं ताकि लॉगिन पेज खुल सके. केवल हाल में प्रशासक पासवर्ड सत्यापित सत्र निजी-पते की सूची और उसका सक्रिय स्विच पढ़ या बदल सकता है; IP प्रवेश सिर्फ सामान्य डैशबोर्ड देता है. लॉगआउट पर कुकी स्वचालित IP प्रवेश रोकती है, जब तक उपयोगकर्ता IP लॉगिन फिर न चुने. TLS नहीं है; LAN HTTP देखने वाला पासवर्ड भी देख सकता है. विश्वसनीय LAN या SSH टनल का उपयोग करें और TCP 8765 इंटरनेट से बंद रखें. मैनुअल `python3 src/web/server.py` आदेश `--bind` और `--password-file` दिए बिना केवल loopback पर रहता है.
- इंटरफ़ेस के नियंत्रण परियोजना की सभी भाषाओं में उपलब्ध हैं। विस्तृत जाँच सारांश और कार्य के लाइव लॉग मौजूदा चीनी Bash जाँचकर्ता से आते हैं और फिलहाल इंटरफ़ेस की सभी भाषाओं में चीनी ही रहते हैं।

## API

`GET /api/auth` लॉगिन स्थिति बताता है; `POST /api/auth/login`, `/api/auth/logout` और `/api/auth/ip-login` सत्र संभालते हैं. `POST /api/auth/security-verify` प्रशासक पासवर्ड जाँचकर सत्र कुकी बदलता है और पाँच मिनट की निश्चित Security Settings अनुमति देता है. `POST /api/auth/change-password` के लिए वही अनुमति और मिलते हुए नए पासवर्ड तथा पुष्टि फ़ील्ड चाहिए; यह root-स्वामित्व वाली पासवर्ड फ़ाइल को परमाणु रूप से बदलता है और सभी मौजूदा सत्र समाप्त करता है.

`GET` और `POST /api/access` उसी सीमित अवधि की अनुमति से केवल RFC 1918 IPv4 या IPv6 unique-local पते तथा अनुमति-सूची का सक्रिय स्विच पढ़ते या बदलते हैं. `GET` और `POST /api/preferences` किसी भी प्रमाणित उपयोगकर्ता के लिए पृष्ठ खोलने पर सोई डिस्क को जगाने की नीति पढ़ते या सहेजते हैं. `POST /api/disks/wake-on-visit` चुने गए जागरण को पृष्ठभूमि में शुरू करता है. `GET /api/disks/<device>/smart` सोए HDD को जगाए बिना आवश्यकतानुसार SMART विवरण पढ़ता है; प्रमाणित `POST /api/disks/<device>/wake` केवल वर्तमान सूची में मौजूद घूमने वाली डिस्क को जगाता है.

`GET /api/snapshot` जाँचकर्ता का संरचित स्नैपशॉट और `GET /api/status` सक्रिय कार्य तथा सीमित लाइव लॉग देता है. `GET /api/jobs/history` सभी संग्रहीत Web कार्यों के सार देता है; `GET /api/jobs/history/<id>` उपलब्ध होस्ट लॉग का सीमित अंत देता है. पहले हटाए जा चुके कार्यों के रसीद रिकॉर्ड विश्वसनीय ढंग से पुनः नहीं बनाए जा सकते. `GET /api/history/<device>` संगतता के लिए अधिकतम 30 SMART काउंटर पंक्तियाँ देता है; `GET /api/history/samples` सभी सूचीबद्ध डिस्क के नमूने देता है. प्रमाणित `DELETE /api/history/samples/<device>/<index>` एक नमूना हटाता है; अंतिम पंक्ति हटने से अगली तुलना का आधार बदलता है. `DELETE /api/jobs/history/<id>` संग्रहीत Web कार्य रसीद और संबंधित लॉग हटाता है.

`POST /api/disks/<device>/sleep` केवल सूचीबद्ध SATA HDD को ATA standby में भेजता है और जाँच चलने पर मना करता है; OS I/O उसे फिर जगा सकता है. `GET` और `POST /api/schedule` त्वरित जाँच अंतराल नियंत्रित करते हैं. `POST /api/jobs` सूचीबद्ध डिस्क पर निश्चित जाँच शुरू करता है. `POST /api/jobs/assess` में `scope` का मान `sata`, `hdd`, `ssd`, `nvme` या `all` और `module` का मान `quick`, `short`, `long`, `speed`, `surface`, `badblocks`, `iface` या `full` हो सकता है; यह मिलती डिस्कों पर एक बैच शुरू करता है. `POST /api/jobs/stop` सुरक्षित रोक माँगता है. अज्ञात API मार्ग 404 देते हैं. जाँचकर्ता का `--json` आउटपुट अंक का स्रोत है; Web सेवा अंक दोबारा नहीं गिनती.

## इंटरफ़ेस और पहुँच

ऊपर Dashboard, Changelog और Settings क्रम से दिखते हैं। Dashboard डिस्क, ध्यान, कार्य (इतिहास सहित) और निर्धारित जाँच पेजों पर सक्रिय रहता है। इन पेजों पर उसे दबाने से मौजूदा पेज नहीं बदलता; Settings या Changelog से दबाने पर `/disks` खुलता है। ऊपर बाएँ का लोगो हमेशा `/disks` से जुड़ा है। चार सारांश कार्ड क्रमशः `/disks`, `/attention`, `/tasks` और `/schedule` खोलते हैं; एक-क्लिक मूल्यांकन डिस्क पेज पर रहता है। Changelog टैब सीधे खोला जा सकने वाला अलग `/changelog` पेज खोलता है।

ऊपरी बाएँ कोने में HDD Health का नाम `/disks` डिस्क डैशबोर्ड से लिंक करता है। ब्राउज़र टैब `src/web/public/favicon.svg` के परियोजना आइकन का उपयोग करता है, जो प्रोडक्शन बिल्ड में शामिल है। ब्रांड के पास अलग संस्करण लिंक परिवर्तन सूची खोलता है. बिना टैग वाले बिल्ड `test-<sha>` (बदली हुई कार्यशाला में `-dirty` सहित) दिखाते हैं; `/api/build` उसी बिल्ड में समाहित संस्करण बताता है. डिफ़ॉल्ट स्नैपशॉट और SMART उत्तर केवल छिपे हुए सीरियल नंबर भेजते हैं; सार्वजनिक स्नैपशॉट में आंतरिक डिस्क ID भी नहीं होती, क्योंकि उसमें सीरियल हो सकता है; अलग प्रमाणित अनुरोध स्पष्ट उपयोगकर्ता कार्रवाई के बाद ही पूरा सीरियल लौटाता है. विवरण छिपाने या बंद करने पर वह फिर साफ हो जाता है.

सेटिंग्स में भाषा, आठ प्रमुख रंग और हल्का/गहरा मोड स्विच हैं, साथ में डिस्क स्लीप नीति है। रंग और मोड पृष्ठ दोबारा खोलने पर अलग-अलग बने रहते हैं; अलग Security Settings पृष्ठ में IP अनुमति-सूची, उसका सक्रिय स्विच और पासवर्ड बदलने का फ़ॉर्म है. पाँच मिनट की अनुमति न होने पर वह प्रशासक पासवर्ड माँगता है. IP से प्रवेश करने वाला भी सामान्य डिस्क और स्लीप नियंत्रण इस्तेमाल कर सकता है, लेकिन सुरक्षा सेटिंग खोलने के लिए प्रशासक पासवर्ड सत्यापित करना होगा. उस अवधि में नया पासवर्ड और पुष्टि भरें; पुराने पासवर्ड को फिर भरना आवश्यक नहीं. परिवर्तन सभी सत्र समाप्त करता है. डिफ़ॉल्ट नीति सोई HDD को सोए रहने देती है; चाहें तो पृष्ठ खुलने पर एक-एक को जगा सकते हैं. SMART विवरण में सीरियल संख्या दिखाने का अलग नियंत्रण है, और विवरण बंद होने पर वह फिर छिप जाती है.

मुख्य पेज पर डिस्क समूह और जाँच का प्रकार अलग-अलग चुन सकते हैं: SATA, HDD, SSD, NVMe या सभी डिस्क; और quick, SMART short/long, speed, surface, badblocks, interface या full। सर्वर वर्तमान डिस्क सूची से चुनकर चुनी हुई जाँच पृष्ठभूमि में चलाता है। केवल full मूल्यांकन वर्तमान संयुक्त स्कोर दे सकता है; SSD/NVMe स्कोर HDD नियमों पर आधारित हैं। सूची में माध्यम और बस के अनुसार SATA SSD या NVMe SSD दिखता है और उपलब्ध तापमान पृष्ठभूमि में पढ़ा जाता है, बिना निष्क्रिय HDD जगाए। विवरण में आकार केवल डिवाइस द्वारा स्पष्ट रूप से बताने पर दिखता है; NVMe या SATA से M.2 आकार का अनुमान नहीं लगाया जाता। SATA और PCIe लिंक के उपलब्ध विवरण smartctl और Linux sysfs से आते हैं। चालू रहने के घंटे दबाकर वर्ष/दिन/घंटे देख सकते हैं।

ध्यान देने वाला कार्ड चेतावनी या समस्या वाली डिस्क दिखाता है। जाँच विवरण में कारण और कटे अंक हैं; पुराने परिणाम में कारण न होने पर पुनः जाँच का संकेत है। कार्य पेज चालू कार्य और खोलने योग्य विस्तृत लॉग दिखाता है, साथ में हाल के 30 कार्यों का अलग इतिहास है। कार्य पूरा, बंद या विफल होने पर सक्रिय रिकॉर्ड हटता है, नई रसीद web-job-history/ में रहती है और डिस्क परिणाम तथा होस्ट लॉग भी बने रहते हैं। निकास कोड 1 या 2 पूरी हुई जाँच में मिली समस्या दर्शाते हैं।

मुख्य पृष्ठ भौतिक डिस्क क्षमता और माउंट किए गए फ़ाइल सिस्टम का उपयोग दिखाता है; UUID से दोहरी गिनती रोकी जाती है। RAID या अनमाउंटेड वॉल्यूम में दोनों का आधार अलग हो सकता है। SSD SMART में NVMe का मानक लिखित डेटा या ज्ञात लॉजिकल सेक्टर आकार वाले ATA आँकड़े दिखते हैं; निर्माता के अज्ञात काउंटर का अनुमान नहीं लगाया जाता। पहचाने गए ZFS पूल का आवंटन भी उपयोग में शामिल है। क्षमता बटन TB/TiB बदलता है और अलग बटन विवरण खोलता है।

कार्य पेज चल रहे कार्य को दिखाता रहता है और अलग इतिहास में हाल के 30 पूर्ण, रोके गए या विफल Web कार्य दिखाता है। उपलब्ध होने पर सीमित विस्तृत लॉग भी खोला जा सकता है। नई रसीदें web-job-history/ में रहती हैं; पहले हटाई गई रसीदें विश्वसनीय ढंग से वापस नहीं मिल सकतीं। ऊपर Dashboard डिस्क, ध्यान, कार्य और निर्धारित जाँच पेजों पर सक्रिय रहता है।

डिस्क पंक्ति मॉडल को शीर्षक और `/dev/` पथ को अलग दिखाती है; विस्तृत दृश्य भी `/dev/` पथ दिखाता है. अलग बटन से विवरण खुलता है. सर्वर एक `<module> --rescan` बैच शुरू करता है और क्लाइंट से मनमाने डिवाइस पथ स्वीकार नहीं करता. केवल `full` मॉड्यूल वर्तमान संयुक्त अंक देता है. `/changelog` पृष्ठ परिवर्तन सूची को Markdown में दिखाता है. सोई HDD को बिना जगाए तापमान पढ़ने के लिए पृष्ठभूमि जाँच `smartctl -n standby` उपयोग करती है; जागरण विकल्प पहले `-n standby` जाँचता है और फिर `smartctl` से गुण पढ़ता है.

## वर्तमान SSD मूल्यांकन और नियंत्रण

पूरा SSD/NVMe मूल्यांकन SMART त्वरित जाँच, छोटी और लंबी स्व-जाँच तथा पूरी डिस्क का केवल-पठन स्कैन चलाता है। गति नमूनाकरण नहीं चलता और केवल धीमा पठन स्वास्थ्य अंक नहीं घटाता। एक ही बैच की सभी जाँचें पूरी होकर सामान्य हों तो अंक 100 होते हैं; SMART समस्याएँ या वास्तविक पठन त्रुटियाँ अंक घटा सकती हैं। चयन में SSD होने पर वेब UI केवल त्वरित, छोटी, लंबी, केवल-पठन स्कैन और पूर्ण मूल्यांकन दिखाता है। क्षमता और लिखे गए डेटा के मान पर क्लिक करके दशमलव और द्विआधारी इकाइयाँ बदली जा सकती हैं। सोई हुई HDD को उसके SMART विवरण से अलग से जगाया जा सकता है।
