# स्थानीय Web UI

Web UI स्थानीय डिस्क के परिणाम, हाल का SMART काउंटर इतिहास, चल रहे कार्य और बदली जा सकने वाली त्वरित जाँच समय-सारणी दिखाता है। यह मौजूदा Bash टूल से चुनी हुई जाँचें शुरू करता है। आंशिक या समय-सीमा पार कर चुके परिणाम को वर्तमान अंक नहीं माना जाता। केवल एक ही बैच का पूर्ण और वैध आकलन संख्यात्मक अंक दिखा सकता है।

ध्यान देने वाली डिस्क के कार्ड अब दर्ज कारण दिखाते हैं। केवल चालू रहने के घंटे स्वास्थ्य अंक नहीं घटाते; पुराने थ्रेशोल्ड संकेत, जिनमें मूल त्रुटि संख्या नहीं है, पुनः जाँच के लिए चिह्नित होते हैं। पुष्टि के लिए पृष्ठ के भीतर संवाद और विवरण में मॉडल के नीचे डिवाइस पथ दिखता है।

## आवश्यकताएँ

- Debian या Ubuntu, Python 3.10+, शामिल Vite संस्करण के अनुकूल Node.js, systemd और `systemd-run`।
- मौजूदा जाँचकर्ता की निर्भरताएँ: `smartmontools`, `util-linux`, `coreutils` और badblocks के लिए वैकल्पिक `e2fsprogs`।
- वेब पेज पर पासवर्ड से साइन इन करें; API सत्र का उपयोग करती है। TCP 8765 केवल विश्वसनीय LAN पर खोलें; HTTP पासवर्ड एन्क्रिप्ट नहीं करता।

## v3.0.0 टैग से Web UI स्थापित करें

`v3.0.0` टैग में Web UI स्रोत है, लेकिन निर्मित `web/dist` नहीं है। Debian systemd होस्ट पर Node.js 20.19+ या 22.12+ और npm स्थापित करें, फिर UI बनाकर इंस्टॉलर चलाएं:

```bash
git clone --branch v3.0.0 --depth 1 https://github.com/CharlesGool/hdd-health-check.git
cd hdd-health-check/web
npm ci
npm run build
cd ..
sudo bash deploy/install.sh
```

## बिल्ड और संचालन

Debian NAS पर पहले से निर्मित संग्रह निकालें, निकाले गए फ़ोल्डर में जाएँ और चलाएँ:

```bash
sudo bash deploy/install.sh
```

स्थापना के बाद `http://<NAS-IP>:8765` खोलें और वेब लॉगिन पर पासवर्ड डालें। पासवर्ड `sudo cat /root/apps/hdd-health-check/web-password` से पढ़ें। अपडेट में पासवर्ड और पुराने ऐप का बैकअप बना रहता है; NAS पर Node.js नहीं चाहिए।

विश्वसनीय checkout से:

```bash
cd web
npm ci
npm run build
cd ..
sudo python3 web/server.py --port 8765
```

`http://127.0.0.1:8765` खोलें। Python प्रक्रिया बिल्ड किया हुआ UI उपलब्ध कराती है; संचालन के समय Node की ज़रूरत नहीं होती। स्रोत checkout और उसका `web/dist` साथ रहने चाहिए। `npm run dev` दूसरे स्थानीय पोर्ट पर Vite चलाता है और `/api` को Python सेवा तक प्रॉक्सी करता है।

स्थायी सेवा के लिए ऊपर का स्थापक उपयोग करें; systemd यूनिट को उसके बनाए पासवर्ड फ़ाइल की आवश्यकता है।

Web सेवा हटाने के लिए `sudo systemctl disable --now hdd-health-web.service` चलाएँ, उसकी इंस्टॉल की गई यूनिट फ़ाइल हटाएँ और `sudo systemctl daemon-reload` चलाएँ। checkout हटाने से पहले सक्रिय अस्थायी जाँचें देखें। CLI के [अनइंस्टॉल निर्देशों](README.md#अनइंस्टॉल-करें) के अनुसार स्थिति डेटा और लॉग को अलग से रखें या हटाएँ।

Codex का `site-preview` पता केवल स्थिर फ़ाइलें दिखाता है। इसमें इंटरफ़ेस और साथ में दिया गया परिवर्तन विवरण दिख सकता है, लेकिन डिस्क डेटा या जाँच शुरू करने के लिए आवश्यक `/api` बैकएंड नहीं है। वास्तविक डेटा के लिए Python सेवा का पता खोलें। दूसरे कंप्यूटर पर `ssh -L 8765:127.0.0.1:8765 user@nas-host` चलाएँ, फिर वहाँ `http://127.0.0.1:8765` खोलें।

## व्यवहार और सीमाएँ

- स्वचालित त्वरित जाँचें शुरू में बंद रहती हैं। सक्रिय करने पर जाँच हर 6–168 घंटे में चलती है। यदि पहले कोई जाँच निर्धारित नहीं हुई है, तो पहली जाँच सक्रिय करने के थोड़ी देर बाद शुरू होती है। समय-सारणी केवल घूमने वाली डिस्क पर चलती है और अस्थायी systemd यूनिट के माध्यम से शुरू होती है।
- मैनुअल जाँच प्रति डिस्क चुनी जाती है। गहरी जाँच केवल घूमने वाली डिस्क के लिए है; स्पष्ट रूप से सूचीबद्ध SSD पर केवल त्वरित जाँच हो सकती है। टूल फिर भी SMART सक्रिय कर सकता है या डिस्क के भीतर स्व-परीक्षण शुरू कर सकता है। सुरक्षित रोक सतह स्कैन की प्रगति बचाती है, लेकिन डिस्क का आंतरिक स्व-परीक्षण रद्द नहीं करती।
- `--no-install` Web सेवा को कार्य शुरू करते समय पैकेज इंस्टॉलेशन मंज़ूर करने से रोकता है। अनुपस्थित निर्भरताएँ अलग से इंस्टॉल करें। Web सेवा केवल तय जाँच नाम और उस समय सूचीबद्ध डिवाइस स्वीकार करती है; कमांड बनाने के लिए shell का उपयोग नहीं करती।
- निजी स्थिति डायरेक्टरी डिफ़ॉल्ट रूप से `/var/lib/hdd-health` और लॉग डायरेक्टरी `/var/log/disk-health` रहती है। `web-schedule.json` स्थिति डायरेक्टरी में 600 अनुमति के साथ रखा जाता है। ब्राउज़र को समान मूल के JSON एंडपॉइंट से स्वास्थ्य परिणाम और हाल का इतिहास मिलता है।
- सेवा Host और Origin जाँचती है। API के लिए पासवर्ड सत्र या अनुमत स्रोत IPv4 चाहिए। IP सूची केवल पासवर्ड सत्र बदल सकता है। पोर्ट इंटरनेट पर न खोलें।
- इंटरफ़ेस के नियंत्रण परियोजना की सभी भाषाओं में उपलब्ध हैं। विस्तृत जाँच सारांश और कार्य के लाइव लॉग मौजूदा चीनी Bash जाँचकर्ता से आते हैं और फिलहाल इंटरफ़ेस की सभी भाषाओं में चीनी ही रहते हैं।

## API

`GET /api/snapshot` जाँचकर्ता का संरचित डिस्क स्नैपशॉट लौटाता है। `GET /api/status` सक्रिय कार्य की स्थिति लौटाता है। `GET /api/history/<device>` SMART काउंटर की अधिकतम 30 पंक्तियाँ लौटाता है। `GET` और `POST /api/schedule` त्वरित जाँच का अंतराल संभालते हैं। `POST /api/jobs` सूचीबद्ध डिवाइस पर तय जाँच शुरू करता है; `POST /api/jobs/stop` सुरक्षित रोक का अनुरोध करता है। अज्ञात API मार्ग 404 लौटाते हैं। जाँचकर्ता का `--json` आउटपुट अंक निर्धारण का स्रोत है; Web सेवा अंक फिर नहीं गिनती।

SMART द्वारा स्लीप मोड की पुष्टि होने पर सूची और विवरण में स्लीप मोड में दिखता है; लंबित तापमान पढ़ा जा रहा है दिखता है और विफल पढ़ाई अज्ञात रहती है। नीति `/var/lib/hdd-health/web-preferences.json` में सहेजी जाती है और शुरू में बंद रहती है। सभी प्रमाणित उपयोगकर्ता IP सूची और नीति बदल सकते हैं; पासवर्ड बदलने के लिए वर्तमान पासवर्ड चाहिए।

## Interface and access

ऊपर Dashboard, Changelog और Settings क्रम से दिखते हैं। Dashboard डिस्क, ध्यान, कार्य (इतिहास सहित) और निर्धारित जाँच पेजों पर सक्रिय रहता है। इन पेजों पर उसे दबाने से मौजूदा पेज नहीं बदलता; Settings या Changelog से दबाने पर `/disks` खुलता है। ऊपर बाएँ का लोगो हमेशा `/disks` से जुड़ा है। चार सारांश कार्ड क्रमशः `/disks`, `/attention`, `/tasks` और `/schedule` खोलते हैं; एक-क्लिक मूल्यांकन डिस्क पेज पर रहता है। Changelog टैब सीधे खोला जा सकने वाला अलग `/changelog` पेज खोलता है।

ऊपरी बाएँ कोने में HDD Health का नाम `/disks` डिस्क डैशबोर्ड से लिंक करता है। ब्राउज़र टैब `web/public/favicon.svg` के परियोजना आइकन का उपयोग करता है, जो प्रोडक्शन बिल्ड में शामिल है।

सेटिंग्स में रूप, सटीक IPv4 बिना-पासवर्ड सूची, डिस्क स्लीप नीति और लॉगिन पासवर्ड हैं। पेज में प्रवेश कर चुका उपयोगकर्ता IP सूची और स्लीप नीति सीधे बदल सकता है। IP से प्रवेश करने पर भी पासवर्ड बदलने का फॉर्म दिखता है; सर्वर वर्तमान पासवर्ड जाँचता है। डिफ़ॉल्ट रूप से सोई हुई HDD नहीं जगती; चाहें तो पेज खुलने पर उन्हें एक-एक करके जगाकर तापमान पढ़ा जा सकता है। डिस्क विवरण में SMART और जाँच टैब हैं; अपडेट अलग Markdown पेज पर हैं।

मुख्य पेज पर डिस्क समूह और जाँच का प्रकार अलग-अलग चुन सकते हैं: SATA, HDD, SSD, NVMe या सभी डिस्क; और quick, SMART short/long, speed, surface, badblocks, interface या full। सर्वर वर्तमान डिस्क सूची से चुनकर चुनी हुई जाँच पृष्ठभूमि में चलाता है। केवल full मूल्यांकन वर्तमान संयुक्त स्कोर दे सकता है; SSD/NVMe स्कोर HDD नियमों पर आधारित हैं। सूची में माध्यम और बस के अनुसार SATA SSD या NVMe SSD दिखता है और उपलब्ध तापमान पृष्ठभूमि में पढ़ा जाता है, बिना निष्क्रिय HDD जगाए। विवरण में आकार केवल डिवाइस द्वारा स्पष्ट रूप से बताने पर दिखता है; NVMe या SATA से M.2 आकार का अनुमान नहीं लगाया जाता। SATA और PCIe लिंक के उपलब्ध विवरण smartctl और Linux sysfs से आते हैं। चालू रहने के घंटे दबाकर वर्ष/दिन/घंटे देख सकते हैं।

ध्यान देने वाला कार्ड चेतावनी या समस्या वाली डिस्क दिखाता है। जाँच विवरण में कारण और कटे अंक हैं; पुराने परिणाम में कारण न होने पर पुनः जाँच का संकेत है। कार्य पेज चालू कार्य और खोलने योग्य विस्तृत लॉग दिखाता है, साथ में हाल के 30 कार्यों का अलग इतिहास है। कार्य पूरा, बंद या विफल होने पर सक्रिय रिकॉर्ड हटता है, नई रसीद `web-job-history/` में रहती है और डिस्क परिणाम तथा होस्ट लॉग भी बने रहते हैं। निकास कोड 1 या 2 पूरी हुई जाँच में मिली समस्या दर्शाते हैं।

मुख्य पृष्ठ भौतिक डिस्क क्षमता और माउंट किए गए फ़ाइल सिस्टम का उपयोग दिखाता है; UUID से दोहरी गिनती रोकी जाती है। RAID या अनमाउंटेड वॉल्यूम में दोनों का आधार अलग हो सकता है। SSD SMART में NVMe का मानक लिखित डेटा या ज्ञात लॉजिकल सेक्टर आकार वाले ATA आँकड़े दिखते हैं; निर्माता के अज्ञात काउंटर का अनुमान नहीं लगाया जाता। पहचाने गए ZFS पूल का आवंटन भी उपयोग में शामिल है। क्षमता बटन TB/TiB बदलता है और अलग बटन विवरण खोलता है।

कार्य पेज चल रहे कार्य को दिखाता रहता है और अलग इतिहास में हाल के 30 पूर्ण, रोके गए या विफल Web कार्य दिखाता है। उपलब्ध होने पर सीमित विस्तृत लॉग भी खोला जा सकता है। नई रसीदें `web-job-history/` में रहती हैं; पहले हटाई गई रसीदें विश्वसनीय ढंग से वापस नहीं मिल सकतीं। ऊपर Dashboard डिस्क, ध्यान, कार्य और निर्धारित जाँच पेजों पर सक्रिय रहता है।

## वर्तमान SSD मूल्यांकन और नियंत्रण

पूरा SSD/NVMe मूल्यांकन SMART त्वरित जाँच, छोटी और लंबी स्व-जाँच तथा पूरी डिस्क का केवल-पठन स्कैन चलाता है। गति नमूनाकरण नहीं चलता और केवल धीमा पठन स्वास्थ्य अंक नहीं घटाता। एक ही बैच की सभी जाँचें पूरी होकर सामान्य हों तो अंक 100 होते हैं; SMART समस्याएँ या वास्तविक पठन त्रुटियाँ अंक घटा सकती हैं। चयन में SSD होने पर वेब UI केवल त्वरित, छोटी, लंबी, केवल-पठन स्कैन और पूर्ण मूल्यांकन दिखाता है। क्षमता और लिखे गए डेटा के मान पर क्लिक करके दशमलव और द्विआधारी इकाइयाँ बदली जा सकती हैं। सोई हुई HDD को उसके SMART विवरण से अलग से जगाया जा सकता है।
